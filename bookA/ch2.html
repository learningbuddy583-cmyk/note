2.1數據分級 Data Hierarchy

🎯 學習重點
  • 由低至高說出數據分級的四個層級：欄位 → 記錄 → 檔案 → 數據庫。
  • 以「學校學生資料庫」為例，說明每一層級放的是甚麼。
  • 解釋管理大量數據時，為何DBMS通常比試算表優勝。

數據分級是「由細到大、層層包含」的組織方式：每個較高層的項目，都是較低層項目的集合。一個欄位存一項屬性；一組欄位構成一條記錄；結構相同的記錄集合成檔案；相關的檔案再集合成數據庫。

四個層級（必背）

欄位 Field實體的一項屬性，例如「學生姓名」
記錄／列 Record某實體的全部欄位，例如一名學生的學號＋姓名＋性別＋班別
檔案／數據表 File結構相同的記錄集合，例如 1A 班 40 名學生的資料
數據庫 Database相關檔案的集合，例如學生表＋教師表＋課室表＋時間表
🧠 記憶口訣：由低至高記「欄·記·檔·庫」。把它想像成寫作：「字 → 句 → 篇 → 書」——字（欄位）組成句（記錄），句成篇（檔案），篇集成書（數據庫）。
✍️ 作答建議：排序題先寫整條鏈「由低至高：欄位 → 記錄 → 檔案 → 數據庫」，再各補一例。注意陷阱：數據庫是檔案的集合，不是記錄的集合。關鍵詞 FieldRecordFile / TableDatabase
把四個層級套進「學校學生資料庫」
階層英文學校例子
欄位FieldSID（學生編號）、ENAME（姓名）、SEX（性別）、CLASS（班別）、CNO（班號）
記錄／列Record「015044、Peter Chan、M、1A、11」——同一名學生的一整列
檔案／數據表File / Table1A 班 40 名學生的記錄，全部都是同樣五個欄
數據庫DatabaseSTUDENT（學生）＋TEACHER（教師）＋CLASSROOM（課室）＋時間表等數據表

常見陷阱：題目說「一欄／一行」，要能立刻對應「欄位／記錄」。

管理大量數據時，數據庫通常比試算表更合適。DBMS讓我們透過GUI有效率地組織、儲存和提取數據，而不必逐句輸入指令。

2.2數據控制 Data Control

🎯 學習重點
  • 解釋「無用輸入，無用輸出」（GIGO）的意思，以及數據控制為何重要。
  • 說出三種常見輸入錯誤及其解決方法。
  • 分辨數據有效性檢驗（由電腦進行）與數據驗證（由人手進行）。
  • 列舉並應用八種有效性檢驗方法，以及檢查數位與奇偶檢測。
  • 說出三種數據驗證方法並各舉一例。

A 無用輸入，無用輸出（GIGO）

輸入數據的方式有很多（人手輸入、網絡傳輸、掃描等），每個環節都可能出錯。當不可靠或不協調的數據被放進分析，就不可能得出有用的結果——這就是GIGO（Garbage In, Garbage Out）。

三種常見輸入錯誤與解決方法
錯誤類型說明例子解決方法
數據來源錯誤數據來源提供了不正確的數據用戶填寫了一個不存在的電郵地址向該地址發送認證碼，要求用戶輸入
轉錄錯誤數據被誤讀、誤聽或誤植OCR 把大楷「I」讀成數字「1」；打字員打錯字拼寫檢查、輸入兩次作驗證、校對
換位錯誤數據的位置或次序被調亂把「$15」記成「$51」；蘋果價錢存進西瓜欄再次輸入作驗證、校對、使用檢查數位
✍️ 辨別竅門：錯在來源＝來源錯誤；錯在字眼＝轉錄；錯在次序＝換位。

B 數據控制的兩大分支

數據有效性檢驗（由電腦進行）檢查數據是否合理、合乎規則；不能保證絕對正確
數據驗證／校驗（由人手進行）核對兩份數據是否相同、一致
✍️ 一秒分辨：問自己「它在查合理還是查相同？」查合理 → 有效性檢驗（電腦）；查相同 → 驗證（人手）。關鍵詞 ValidationVerification

C 數據有效性檢驗方法（點卡片查看）

有效性檢驗不能保證輸入的數據絕對準確，只能確保數據合理並符合某些規則。它通常由系統或程式執行，常見於政府預約服務、網上購物平台等網上表單。同一個欄位可以同時套用多種檢驗方法。

🧠 記憶口訣：想像自己在填一張報名表——先完整、選固定、對類型、限範圍、查長度、看格式、前後一致、學號唯一。（完·固·類·範·長·格·一·唯）

數據類型要一致（類型檢查的由來）

為方便組織和分析，同一欄位的數據應屬同一數據類型。若類型混雜，排序會亂、計算會出錯（例如把「八十五」與 91 相加只會得出錯誤）。

整數 Integer可以是正數或負數：學生人數、年齡
浮點數／實數 Real可有小數位：分數、身高
字串／文字 String英文字母、數字、中文字、符號：姓名、地址
布爾 Boolean只能是 TRUE 或 FALSE：是否合格
✍️ 經典陷阱：像 015034 這類學生編號必須以文字儲存，因為數字無法保留前置的零。

D 檢查數位

檢查數位是由特定算法生成、附加在數字數據末尾的一或多個數位，用於身份證號碼、書號、信用卡號碼等。若數據的檢查數位與算法算出的不符，該數據即為無效。

實驗⑥

香港身份證號碼檢查數位計算機

輸入「1–2 個英文字母＋6 個數字」（如 Y147036）可計算檢查數位；若在末尾加上檢查數位（如 D246246(A)）則可驗證。

算法：只有一個字母時在開首補一個空格；A＝10、B＝11……Z＝35，空格＝36；比重依次為 9、8、7、6、5、4、3、2、1；求加權和再除以 11，餘數為 0 即有效。求檢查數位時用「11 − 餘數」（餘數為 0 時檢查數位是 0）。

E 奇偶檢測

電腦內部以二進制儲存數據，可以在最後加上一個「奇偶位 parity bit」去檢查傳送途中有沒有出錯。

按我顯示更多內容
  • 奇偶檢測是加 1 個奇偶位 來做簡單錯誤偵測的方法。
  • 偶數檢測：整組 9 位元（資料 8 + 奇偶 1）中 1 的數目要是 雙數。
  • 奇數檢測：同理，總數要是 單數。
  • 怎樣決定奇偶位：先數資料位元中有幾個 1，再選 0/1 把總數調成雙數或單數。
  • 偵測能力：能偵測單一（或任何 奇數個）位元錯誤，但偵測不到 偶數個 位元同時出錯。
  • 考試題：計算奇偶位，或判斷一組 9 位元代碼是否有效。
  • 奇數檢測：整組二進制裡面「1」的總數要是奇數。
  • 偶數檢測：整組二進制裡面「1」的總數要是偶數。
實驗⑦

奇偶檢測：翻位元、立刻看整組代碼是否有效

自由試玩：選一種檢測，點任一位元在 0/1 之間翻轉，下方即時告訴你整組代碼是否有效。**最後一格（橙色）就是奇偶位**——你也可以動它，把整組調成有效。

F 數據驗證（由人手進行）

數據驗證用來確認數據在媒體之間傳輸（例如由紙本表格輸入電腦）時，仍然準確且一致。

方法做法例子
輸入數據兩次同一位操作員輸入兩次，比較兩份複本是否相同設定新密碼時要輸入兩次
雙重數據輸入兩位操作員各自輸入同一批數據，再互相比較聘請兩人各自把紙本問卷輸入電子表單
校對數據由另一位操作員把已輸入的數據與原始檔案核對把成績單列印出來與試卷互相核對
🧠 記憶口訣：驗證三招記「打兩次、兩個人、對原件」。
✍️ 作答格式：寫「方法＋由誰做＋比較甚麼」。例：「雙重數據輸入：由兩位操作員分別輸入同一份表格，系統比較兩份複本是否相同。」
實驗⑧

有效性檢驗 還是 驗證？

判斷以下做法是「由電腦查合理（有效性檢驗）」還是「由人手查相同（驗證）」。這是 DSE 常考辨析。

2.3數據庫的功能 Functions of a Database

🎯 學習重點
  • 說出數據庫的三大功能：組織、儲存、提取。
  • 解釋為何要謹慎選擇欄位的數據類型。
  • 解釋索引如何加快數據提取，以及它需要付出甚麼代價。

A 組織

數據庫中的數據按數據庫結構組織。良好的結構可讓不同數據表之間的傳遞更流暢，並減少數據重複；為每個欄位選對數據類型，數據才會一致、易於分析。

示例：學生數據表的結構
欄位名稱數據類型說明
SID字串學生編號；數字無法儲存前置零，故必須存為文字
NAME字串學生姓名
SEX字串學生性別
CLASS字串學生所屬班別
CNO整數班號——是數字，方便排序

B 儲存

我們可以用SQL或圖形用戶界面（GUI）在數據庫中插入新記錄、更改或刪除現有記錄；亦可匯入 CSV 等格式的檔案，短時間內建立大量記錄。

操作SQL 示例
插入記錄INSERT INTO STUDENT (SID, ENAME, SEX, CLASS, CNO) VALUES (…);
提取記錄SELECT * FROM STUDENT WHERE SEX = "M";
提取並排序SELECT * FROM STUDENT WHERE SEX = "M" ORDER BY ENAME;

C 提取（與索引的作用）

沒有索引時，DBMS 須逐行讀取數據表，最壞情況要讀完整張表。索引就像書本的目錄：只存索引欄位和指向記錄的指標。

✍️ 索引的代價：學生姓名更改或加入新記錄時，索引表都必須更新。更新費時間、儲存佔空間，所以只應在必要時才建立索引。
🧠 記憶口訣：索引＝書本目錄——查得快，但書一改動就要重新印一次目錄。
實驗⑨

有索引 vs 無索引：數一數讀了幾次

選定目標姓名，分別按兩個按鈕：逐行搜尋由頭逐項讀；二分搜尋在已排序的索引上每次篩走一半，只探測少數幾項。比較讀取／探測次數。

2.4檔案存取方式 File Access Methods

🎯 學習重點
  • 比較順序存取與直接存取取得數據的方式。
  • 說出使用這兩種方式的儲存設備。
  • 說出兩者的優點、缺點及常見用途。

數據可以儲存在不同的儲存設備中，而設備決定了如何存取數據。常見的檔案存取方式有兩種：順序存取和直接存取。

A 順序存取

使用順序存取的設備由頭開始按順序寫入數據；要存取特定數據，系統須依次搜索前面的所有數據。因此速度取決於目標數據的位置，平均比直接存取慢。

磁帶（只用順序存取）要聽後段歌曲，必須先把前面的帶子捲過去

B 直接存取

每個儲存位置都有獨一無二的位址，系統可直接跳到該位置存取數據，無須搜索其他地方。速度穩定，一般較快。

  • 檢驗方法命名：給一條表單規則，說出是哪種檢查
  • 檢查數位與奇偶檢測：計算／驗證，並解釋「通過 ≠ 正確」
  • 索引：為何加快提取、維護它需要甚麼代價
  • 存取方式：就情境選擇順序或直接存取並說明理由
